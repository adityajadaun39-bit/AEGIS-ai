\section{Ten High-Probability Examiner Questions \& Model Answers}
Below are 10 rigorous model answers prepared for high-probability examiner inquiries.

\subsection{Question 1: Prompt Defenses vs. External Gateways}
\textbf{Examiner:} \textit{``Why can't we simply use a stronger system prompt or prompt guardrail to prevent indirect prompt injection?''} \\
\textbf{Designated Respondent:} Member 2 / Farhan Mallik. \\
\textbf{Model Answer:} \\
\textit{``In modern transformer architectures, system instructions and untrusted document tokens share the exact same context window and token stream. The self-attention mechanism computes pairwise dot-product affinities across all tokens indiscriminately. An adversary can employ delimiter hijacking, semantic roleplay, or few-shot instruction overrides to convince the model that previous instructions are deprecated. Relying on an LLM to police itself is fundamentally insecure. AEGIS treats the neural network as an untrusted computation engine and enforces security externally at the tool proxy layer.''}

\subsection{Question 2: Overriding Human Approval}
\textbf{Examiner:} \textit{``Isn't the human in the loop supposed to be the ultimate security authority? Why does AEGIS override a human approval?''} \\
\textbf{Designated Respondent:} Member 3. \\
\textbf{Model Answer:} \\
\textit{``This is the central innovation of AEGIS. Empirical red-teaming proves that human reviewers suffer from alert fatigue and are easily socially engineered. A compromised agent does not propose 'May I exfiltrate the database?'; it constructs plausible justifications such as 'Routine backup to Frankfurt staging server'. Human approvers cannot inspect multi-turn token lineage in real time. AEGIS enforces Theorem 1: The Provenance Dominance Invariant. If causal lineage originates from untrusted data, the gateway mathematically nullifies the human approval and denies execution.''}

\subsection{Question 3: Latency Overhead \& Agentic Friction}
\textbf{Examiner:} \textit{``What is the latency overhead of AEGIS? Does it introduce perceptible friction into agent reasoning loops?''} \\
\textbf{Designated Respondent:} Member 4 / Member 2. \\
\textbf{Model Answer:} \\
\textit{``Our empirical benchmarks demonstrate a median gateway latency of only 23.29 milliseconds across 300 runs, and a mean single-scenario latency of 17.98 milliseconds. We achieve this by ordering inspection sequentially from fastest to heaviest: HMAC authentication ($< 0.1\text{ ms}$), regex heuristic and DLP scans ($< 1.8\text{ ms}$), in-process declarative policy check ($< 0.5\text{ ms}$), and optional on-device ONNX neural inference ($< 25\text{ ms}$). Compared to typical LLM API generation times of 1,000 to 3,000 milliseconds, AEGIS adds less than 1\% latency overhead.''}

\subsection{Question 4: SQLite WAL Concurrency vs. Distributed DBMS}
\textbf{Examiner:} \textit{``Why did you implement SQLite with WAL mode instead of PostgreSQL or MongoDB?''} \\
\textbf{Designated Respondent:} Member 4. \\
\textbf{Model Answer:} \\
\textit{``For an edge-deployable security gateway, SQLite provides a zero-configuration, zero-daemon, serverless architecture. By configuring SQLite with Write-Ahead Logging (\texttt{PRAGMA journal\_mode = WAL}) and a 5,000ms busy timeout, we decoupled concurrent readers from append-only writers. We empirically verified 50 concurrent worker threads processing 23.3 requests per second with zero database lock errors. Furthermore, our repository pattern abstracts storage operations, allowing drop-in migration to PostgreSQL for distributed enterprise clusters by changing a single connection URI.''}

\subsection{Question 5: Parameter Tampering \& TOCTOU Prevention}
\textbf{Examiner:} \textit{``How does AEGIS prevent parameter tampering between the time an approval is granted and when the action is executed (TOCTOU)?''} \\
\textbf{Designated Respondent:} Farhan Mallik. \\
\textbf{Model Answer:} \\
\textit{``We implement cryptographic payload binding in \texttt{approval\_engine.py}. When an approval request is created, \texttt{calculate\_payload\_hash} serializes the Pydantic action model with canonical alphabetical key sorting and zero whitespace, computing a deterministic SHA-256 digest. When the action is submitted with an \texttt{approval\_id}, the gateway recalculates the SHA-256 digest of the execution payload. If a single character—such as an email destination or financial transfer amount—has been modified, \texttt{hmac.compare\_digest} fails and execution is denied immediately.''}

\subsection{Question 6: Multi-Agent Mesh Coordination}
\textbf{Examiner:} \textit{``How does AEGIS handle multi-agent mesh communication where Agent A delegates a sub-task to Agent B?''} \\
\textbf{Designated Respondent:} Farhan Mallik / Member 3. \\
\textbf{Model Answer:} \\
\textit{``AEGIS treats multi-agent delegation as a transitive graph propagation problem. When Agent A dispatches an intermediate prompt or parameter set to Agent B, the gateway requires that Agent A pass its verified \texttt{provenance\_context\_id}. The gateway resolves the parent lineage, merges it into Agent B's execution context, and computes the new lattice bounds via Meet ($\sqcap_I$) and Join ($\sqcup_C$). If Agent A ingested untrusted data, Agent B inherits the tainted label transitively, preventing multi-hop laundering.''}

\subsection{Question 7: Handling False Positives in Threat Detection}
\textbf{Examiner:} \textit{``What happens if the Tier 2 ONNX model falsely classifies a benign academic discussion about security as prompt injection?''} \\
\textbf{Designated Respondent:} Member 2. \\
\textbf{Model Answer:} \\
\textit{``AEGIS employs defense-in-depth where threat detection scores inform risk levels without breaking data flow unilaterally for benign read tools. An elevated threat score tags the newly generated provenance node with untrusted integrity. This does not block the agent from analyzing the document; it merely prevents the agent from invoking outbound high-privilege side-effecting sinks (e.g., sending emails or modifying files) using data derived from that document. Benign operations that do not egress data continue unimpeded.''}

\subsection{Question 8: Acyclicity Enforcement in Provenance Graphs}
\textbf{Examiner:} \textit{``How does the system ensure that the provenance graph remains a Directed Acyclic Graph (DAG) during recursive reasoning loops?''} \\
\textbf{Designated Respondent:} Member 3. \\
\textbf{Model Answer:} \\
\textit{``Acyclicity is enforced at two distinct layers. Structurally, the \texttt{Provenance} Pydantic schema contains an explicit validator asserting that a node's \texttt{source\_id} can never appear in its \texttt{parent\_source\_ids} tuple. Temporally, every provenance node is stamped with a monotonic, server-generated UTC timestamp, and parent nodes must strictly precede child nodes in time ($t_{\text{parent}} < t_{\text{child}}$). This temporal ordering makes cycles mathematically impossible.''}

\subsection{Question 9: Direct Database Tampering Resilience}
\textbf{Examiner:} \textit{``Can an attacker compromise security by directly editing or injecting SQL into the SQLite database?''} \\
\textbf{Designated Respondent:} Member 4. \\
\textbf{Model Answer:} \\
\textit{``First, the SQLite database file resides within the gateway's isolated operating system container, inaccessible to external network callers or the agent runtime. Second, every database query across the entire codebase uses parameterized SQL queries via SQLite prepared statements, preventing SQL injection. Third, approval hashes are verified against incoming in-memory payloads using cryptographic digests, preventing forged approval records from executing without valid payloads.''}

\subsection{Question 10: Horizontal Scaling in Distributed Kubernetes Clusters}
\textbf{Examiner:} \textit{``How does AEGIS scale horizontally if traffic exceeds the limits of a single SQLite node?''} \\
\textbf{Designated Respondent:} Member 4 / Farhan Mallik. \\
\textbf{Model Answer:} \\
\textit{``While local SQLite WAL mode delivers outstanding performance for edge deployments (23.3 req/s under 50 concurrent workers), AEGIS was engineered following the 12-factor application pattern. The gateway core is completely stateless. To scale horizontally across Kubernetes pods, the SQLite storage adapter is replaced with PostgreSQL or Amazon Aurora by updating the database connection string. Shared distributed caching for approval state can be backed by Redis, enabling linear horizontal scaling across dozens of gateway replicas.''}
